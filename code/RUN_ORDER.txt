Run order (Python 3, standard library only). Run every command from the project folder.
Steps marked [paid] send requests to OpenRouter (key in OPENROUTER_API_KEY); every other step is free.
Steps marked [author] are filled in by hand before the next command.
Outputs of the scoring and analysis steps must be outside data/ and paper/ (the scripts refuse otherwise);
this run order uses results/.

A. Candidate pool

1. Data: data/raw/retraction_watch.csv
   Retraction Watch data for 13 Nov 2026 (Crossref commit 560ad745cb621e240501422ad485bd81b4590860),
   downloaded 14 Nov 2026. Pinned URL (gives exactly this file):
   https://gitlab.com/crossref/retraction-watch-data/-/raw/560ad745cb621e240501422ad485bd81b4590860/retraction_watch.csv
   SHA-256 4d0509f648ec6dc7f7de43a2260943ed15c56b239d882d73f468f4f40ef917dd (68,092,153 bytes)
2. python3 -I code/pool.py data/raw/retraction_watch.csv 2026-01-01 data/work/pool_jan.json
   Date, type, health (HSC), reason and DOI rules. Prints the funnel.
   The pool starts wide (1 Jan 2026); the study's window (retracted from 1 Jul 2026) is applied in step 5.
3. python3 -I code/openalex.py data/work/pool_jan.json data/work/pool_jan_oa.json
   Citations, abstract presence, subfield from OpenAlex (queried 14 Nov 2026; counts change over time).
4. python3 -I code/pubmed.py data/raw/retraction_watch.csv data/work/pool_jan_oa.json data/work/pool_jan_full.json
   Missing abstracts from PubMed E-utilities.
5. python3 -I code/count.py data/work/pool_jan_full.json data/work/candidates.csv
   Count table per start date (the study uses the 1 Jul 2026 row) and the candidate CSV.

Model catalogue snapshot: data/snapshots/openrouter_models_2026-11-13.json
(OpenRouter https://openrouter.ai/api/v1/models, retrieved 13 Nov 2026).
"Lab" vs "clinical/other" is a rough split by OpenAlex subfield, not a screening decision.

Power check (Methods section 3.6), independent of the other steps:
python3 -I code/power.py   (about a minute; fixed seeds, so the output is identical on every run)

E. Live check on the free model, then the pilot (section 3.1, "Order of work", step 7; section 3.6, "Run checks")

22a. Live check, free model only (no cost; ERNIE has a daily limit of 1,000 requests):
    python3 -I code/run_tests.py data/work/pilot/items.json data/logs/free-check --phase "dry run" --models ernie --budget 1
    python3 -I code/check_run.py data/logs/free-check
23. [paid] python3 -I code/run_tests.py data/work/pilot/items.json data/logs/pilot --phase pilot --budget USD
    python3 -I code/check_run.py data/logs/pilot
    check_run.py reads the logs only. It reports, per model: the service tier served, the provider and model
    returned, the price charged against the pinned endpoint's price, and whether conversations with tool calls
    ended in a usable answer (the Responses API path of GPT-6 Luna and GPT-6.1 Sol has never run live).
    Do not start the main run while it reports a FAILED check. Review NOTE entries too: missing tier/price
    evidence or an unexercised tool path is not a successful validation. Exit 0 means no detected failure,
    not that every check is verified. A non-calling model needs a separate documented tool-path check.
24. Score the pilot as in steps 28-36, with data/work/pilot/items.json, data/logs/pilot, results/pilot and
    --pilot on human_check.py prepare and analysis.py.

Every paid step resumes where it stopped: run the same command again. A run refuses a log folder made with
different items, models or settings, and only one process may use a log folder at a time.
--budget is a scheduling guard (a reserve per request), not a billing cap; "USD" stands for the amount approved
for that step.
